# 안내사 QA 검증 불가 34건 — 필요한 데이터·API 정리

`docs/QA_안내사.md` 실행 결과 중 ⏸(검증 불가) 항목을 **왜 막혔는지** 기준으로 나눴습니다.

- **A. 데이터만 넣으면 됨** — API·필드는 이미 있고, 서버에 해당 상태의 레코드가 없어서 막힘
- **B. 기존 API에 필드 추가** — 엔드포인트는 있으나 앱이 필요한 값이 응답에 없음
- **C. 새 API 필요**

---

## A. 데이터만 넣으면 되는 것 (26건)

### A-1. 안전 관리 / 대시보드 — 경고·위험 인원
- **화면**: 안전 관리(`SafetyManagementView`), 대시보드 상단 요약
- **API**: `GET /api/monitoring/trips/{id}/latest/`, `.../summary/`
- **쓰임**: `overall_status`(safe/warning/danger/stale/offline)로 행 배경·점 색을 칠하고, summary의 `warning`/`danger` 카운트를 상단 카드에 띄웁니다.
- **현재**: 참가자 5명 전원 `unknown`, summary도 `warning=0 danger=0`. 심박·SpO₂ 스냅샷이 아예 없습니다.
- **요청**: 참가자 중 최소 1명씩 **warning / danger / stale** 상태가 되도록 `HealthSnapshot`을 넣어주세요. 심박 이상(예: 130bpm)·SpO₂ 저하(예: 88%) 각각 한 건씩이면 판정 로직 전체를 볼 수 있습니다.
- **막힌 케이스**: S-03 상태 색상, S-04 정렬(위험 우선), S-05 심박/SpO₂ 표시, S-06 미측정 표기, H-02 요약 카드 수치, H-05 위험 강조

### A-2. 알림 센터 — 알림 0건
- **화면**: 알림(`NotificationCenterView`)
- **API**: `GET /api/monitoring/trips/{id}/alerts/`, `POST .../incidents/{id}/acknowledge/`
- **쓰임**: 알림 목록·심각도 뱃지, [확인] 버튼이 acknowledge를 호출하고 목록에서 사라집니다.
- **현재**: alerts 응답이 빈 배열이라 목록·확인·필터를 전혀 못 눌러봤습니다.
- **요청**: 인시던트를 1~2건 열어 알림이 쌓이게 해주세요(위 A-1의 이상 스냅샷을 넣으면 자동 생성될 것으로 보입니다).
- **막힌 케이스**: A-01~A-07 전부

### A-3. 관광객 위치 확인 — 위치 스냅샷 없음
- **화면**: 관광객 위치 확인(`TouristLocationView`)
- **API**: `GET /api/monitoring/trips/{id}/latest/` 의 `location{latitude,longitude,measured_at,accuracy_m}`
- **쓰임**: 핀 좌표, 역지오코딩 주소, "n분 전" 갱신 표기, 지오펜스 원과의 이탈 여부.
- **현재**: 전원 `location: null` → 화면 진입 버튼 자체가 비활성이라 8개 케이스 모두 미검증.
- **요청**: 참가자 몇 명에 **LocationSnapshot**을 넣어주세요. 범위 안 1명 / 범위 밖(이탈) 1명 / 오래된 좌표(10분 이상 전) 1명이면 T-02·T-03·T-05·T-07을 한 번에 볼 수 있습니다.
- **막힌 케이스**: T-01~T-08 전부

### A-4. 여행 미배정 / 빈 일차
- **화면**: 대시보드, 여행 상세
- **API**: `GET /api/v1/trips/`, `GET /api/trips/{id}/schedules/`
- **쓰임**: 배정된 여행이 없을 때·일정이 없는 일차일 때의 빈 상태 문구.
- **요청**: 여행이 배정되지 않은 매니저 계정 1개, 일정이 비어 있는 일차 1개.
- **막힌 케이스**: H-08 빈 상태, N-09 빈 일차, G-02 미설정 일차(전일 복사 제안)

### A-5. 여권번호
- **화면**: 안전 관리 표
- **API**: `GET /api/v1/trips/{id}/participants/` 의 `traveler.passport_number`
- **쓰임**: 마스킹 표시(`ABC***123`)와 👁 토글.
- **현재**: 전원 빈 문자열이라 마스킹 로직 미검증(빈 값 처리만 확인).
- **요청**: 데모 참가자 여권번호 채워주세요.
- **막힌 케이스**: S-07 마스킹 토글

## B. 기존 API에 필드만 추가하면 되는 것 (5건)

| 화면 | 엔드포인트 | 추가 요청 필드 | 앱에서 쓰는 방식 |
|---|---|---|---|
| 안전 관리 | `.../latest/` | `heart_rate_status`, `spo2_status` | 지금은 `overall_status` 하나뿐이라 **어느 지표가 이상인지** 알 수 없어 심박·SpO₂ 칸을 개별로 못 칠합니다 |
| 알림 | `.../alerts/` | `participant_id`, `is_read`(또는 `read_at`) | 알림 → 해당 관광객 위치 화면으로 이동, 읽음/안읽음 구분 |
| 알림·안전 관리 | `.../incidents/` | `distance_m` | 이탈 알림에 "허용 범위에서 n m 벗어남" 표기 |
| 대시보드 | `.../summary/` | `escaped`(범위 이탈 인원 수) | 상단 요약 카드의 "이탈" 칸 — 지금은 latest를 앱이 세고 있습니다 |
| 대시보드 | `GET /api/v1/trips/{id}/` | `today_day_number` | 오늘이 몇 일차인지 앱이 날짜 계산으로 추정 중 (서버 기준으로 통일 필요) |

## C. 새 API가 필요한 것 (1건)

| 화면 | 필요한 것 | 사유 |
|---|---|---|
| 공지 설정 | `DELETE /api/v1/notices/{id}/` | `OPTIONS` 응답이 `GET, PATCH, HEAD, OPTIONS` — 삭제 미지원. 현재 ⋮ 메뉴의 [삭제]는 호출 시 405가 납니다 |

### 참고 — 재게시 정책
`POST /api/v1/notices/{id}/publish/` 가 보관(archive)된 공지에 대해 409 `Archived notices cannot be republished`를 반환합니다. 의도된 정책이면 그대로 두겠습니다(앱은 "되돌릴 수 없다"고 미리 경고합니다). 되돌리기를 허용할 계획이면 알려주세요.
