## 2. 테스트 데이터

### 관광객 계정 (현재 36명 모두 미발급이라 관광객 화면 검증 불가)

`login_id` / 임시 비밀번호를 전달해 주세요. 아래 경우를 하나씩 부탁드립니다.

| # | 조건 | 검증 목적 |
|---|---|---|
| A | 여행 1개, **오늘 진행 중** 여행 | 홈·일정·공지·채팅 전체 흐름 |
| B | A와 같은 조건, 최초 비밀번호 변경 전 상태 | `PASSWORD_CHANGE_REQUIRED` → 변경 화면 → 재로그인 |
| C | 여행 **2개 이상** 참가 | `TRIP_SELECTION_REQUIRED` 처리 |
| D | 여행 종료 후 3일 지난 계정 | 토큰 만료 → 로그인 화면 |

### 진행 중 여행 날짜

검증용 trip 1·2가 9/10에 끝나서 `today_day_number`가 모두 `null`입니다. 오늘 날짜를 포함하도록 일정 날짜를 옮기거나, 진행 중 여행을 하나 추가해 주세요. 그래야 홈의 「오늘의 일정」·진행률을 검증할 수 있습니다.

## 3. API 추가·수정

| 항목 | 이유 |
|---|---|
| 매니저 일정 응답(`/api/trips/{id}/schedules/`)에 장소 이미지 포함 | 지금은 `place_name`만 있어 전체 일정에 사진 표시 불가 |
| 최소 지원 버전 API (`min_ios_version`, `store_url`) | 스플래시 강제 업데이트 팝업 |
| 로그인 실패 시 `remaining_attempts` | 실패 횟수 (n/5)를 서버 기준으로 표시. 지금은 기기에서 셈 |
| 로그인 잠금(429) 동작 확인 | 없는 아이디로 7회 실패해도 401만 옴. 실제 계정에서 5회 → 10분 잠금 + `Retry-After`가 오는지 확인 부탁 |
| 동시 로그인 감지 | 지금은 새 로그인 시 기존 세션이 확인 없이 끊김. 기획의 「차단하고 로그인하시겠습니까?」를 위해 409 + 코드 반환, 강제 로그인 필드 필요 (앱은 `force_login` 가정) |
| 약관 동의 버전 필드 | 약관 개정 시 재동의 판단 |
| 건강정보(민감정보) 동의 필드 | 개인정보 동의와 별도 저장 필요 (법적 요건) |
| 안내사 약관 동의 저장 API | 현재 관광객만 있음 |
